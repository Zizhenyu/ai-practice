### 判定

Map 3 保留了 Bob、Erin 的负责人和期限；Map 4 只有后续片段，却写成对账、复盘未提供负责人和期限。
Reduce 同时保留正确待办，又写“对账、复盘：后续在本线程更新；未列负责人和期限。”以及全局未知项，形成自相矛盾。
这是分块局部缺失被误当成全文缺失，不是原文没提供，也不是 mock 的机械截取。
Single 没有这项矛盾。此外 Reduce 仍列无关的主题色、午餐讨论，冗余较多；字符切块还把 09:53 的错误口径拆断，影响可读性。

## 改进设计与验收

先让 Map 输出事实表：`task / owner / due / status / source / scope`，将“本块未出现”与“原文明确未定”分开。
Reduce 按任务合并：已有明确证据的 owner/due 不得被其他块的缺失覆盖；真正冲突保留来源待核查。
分块优先按发言边界，并携带必要相邻上下文，避免切断数字更正。
验收至少检查 Bob=明天14:00、Erin=今天12:00、Chen=今天17:00提交方案，且最终未知项不得否定这些已知字段；FAQ负责人仍须未定。
这些是下一轮待验证的改进，本次没有冒称修改后已通过。单个样本不能推出 Map-Reduce 总体更差。
