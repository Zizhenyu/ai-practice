# 《木兰辞》：同一份输入，不同评估标准 · Demo Spec

状态：已实现并测试（2026-09-15）。入口 `compare_evaluators.py`，运行记录见 `MULAN_TEACHER_GUIDE.md`。本版本取代“文学改写质量评估”方案。

## 1. 与本节讲授内容的关系

Session 5 对应 L4“评估入门与 Prompt 工程”。教案已有明确目标：区分要点覆盖率与摘要质量评分，能根据原文审查 Judge 的依据。

本 Demo 用大家熟悉的《木兰辞》（《木兰诗》）替换工程事故材料，降低背景知识门槛。核心实验：

> 固定原文、摘要任务和待评摘要，仅切换评估方法，观察每种分数回答什么问题，以及遗漏什么问题。

不要求改写长诗，不现场生成作品，不新增文学创作评分体系。沿用现有方法：

- `judge.py`：逐项判断 must_include 是否被覆盖，计算覆盖率。
- `judge_google.py`：根据原文和任务，按既有四项标准给出整体 1–5 分及引文。

两者都是 LLM-as-judge，但评价问题、上下文及输出尺度不同。不是比较两个模型，也不能把 100% 与 5 分换算成同一种“准确率”。

## 2. 固定什么，改变什么

“同一份输入”有两层：

1. 摘要任务输入：固定《木兰辞》全文和同一摘要要求。
2. 评估对象：同一份固定摘要分别送入两种评分器，两条路径不能分别生成摘要。

只有原文、没有待评输出，无法演示现有摘要评分器。因此还需准备固定摘要作为被评对象，这不是新增写作练习。

主展示先用一份“覆盖完整但有额外编造”的摘要，再用两份控制样例解释指标边界。三份摘要均分别运行两种方法，形成配对结果。

固定原文版本、摘要文字、任务要求、要点清单、模型及调用参数。不向模型提供人工分数或“好/坏”等标签。

注意：按现有实现，覆盖率方法只读取摘要与单条要点；综合评分读取原文、任务和摘要。因此这里比较的是两套评估方法，并非只替换评分 Prompt、其余上下文完全相同的消融实验。报告必须明确这一差异。

## 3. 原文、任务与 must_include

### 原文

实现时核验一份公版《木兰辞》全文，包含结尾双兔比喻，按段编号 p01、p02 等。记录来源 URL、访问日期和版本说明，不复制现代译文或赏析。

固定版本，不混用异文；评分仅依据给定原文，不引入影视改编、其他传说或模型记忆。避免把“十二年”等修辞数字的唯一字面解释设为必考点。

### 摘要任务

> 用一段简洁的现代中文概括《木兰辞》的主要故事。包括从军缘由、征战经历、受赏后的选择、返乡及身份揭晓。忠于给定原文，不加入原文没有交代的人物关系或重要事件。

不设硬性字数门槛，避免将字数计算变成第三条教学主线。

### 要点清单

每项等权，最终 fixture 中给出对应原文段落 ID 和连续引文。

| ID | 必须涵盖的要点 |
|---|---|
| k1 | 父亲被征召，木兰代父从军 |
| k2 | 木兰离家征战，经历艰苦军旅后归来 |
| k3 | 木兰受赏后不愿任官，请求返乡 |
| k4 | 木兰回家与家人团聚，换回女装 |
| k5 | 同行伙伴此时才发现木兰是女子，感到惊讶 |

不要求精确服役年数或逐项采购细节。未翻译结尾双兔比喻不算遗漏核心情节。清单必须与任务要求对齐，但不是全文每个细节的穷举。

## 4. 固定摘要设计

用 A/B/C 中性 ID，构造标签、人工参考分和说明放在教师文档，不传入 Judge。

### A：完整、忠实的基线

覆盖 k1–k5，事实有据、简洁通顺。预期覆盖率较高，综合质量较高。

### B：保留完整内容，额外添加编造（主例）

在 A 上追加一个无依据的重要断言，例如“返乡后，木兰与一位同行将领成婚”。最终措辞在实现时结合原文审稿确定。

设计关键：保留所有正确要点，错误是额外新增。不能把辞官返乡替换成留朝任官，否则覆盖率也可能下降，无法清楚展示覆盖完整仍可能失真。

### C：正确但遗漏的控制例

仅保留 k1、k2，不写 k3–k5；现有内容准确，不新增错误。

### 人工参考矩阵

| 摘要 | 覆盖率参考 | 综合评分参考 | 解释 |
|---|---|---|---|
| A | 5/5 = 100% | 5/5 | 内容完整、事实有据 |
| B | 5/5 = 100% | 1/5 | 覆盖指标未惩罚要点之外的编造 |
| C | 2/5 = 40% | 2/5 | 正确但未完成核心摘要任务 |

以上是人工构造的教学预期，不承诺真实模型一定给出相同结果。若覆盖率 Judge 因额外错误将 B 的某个要点判为 NO，应展示实际结果，讨论它是否偏离了逐点覆盖问题，不能修改或挑选结果强行证明预期。

## 5. 两种方法的比较

### 方法一：要点覆盖率

复用 `judge.py` 的逐点问题：摘要是否充分或实质覆盖当前要点？输出 YES/NO。

`coverage = 命中数 / 要点总数`

输出各项 HIT/MISS、分子分母及覆盖率。它回答“要求讲的内容讲到了多少”，不系统检查每一句是否有依据，也不完整评价流畅性、冗长与额外编造。

每份摘要五个应用层调用，三份共十五个。新增接口严格解析 YES/NO；非法响应/API 异常记为 error，不能静默算作 MISS。任一项失败时覆盖率为 null，保留成功项结果。

### 方法二：有原文依据的综合质量

复用 `judge_google.py` 和现有 `prompts/summarization_quality.md`，不新建文学 rubric：

- instruction_following：完成任务要求。
- groundedness：事实有原文依据。
- conciseness：简洁且保留关键信息。
- fluency：表达清楚流畅。

沿用整体 1–5 分及从低分条件开始判断的规则，不平均四项分数。每份摘要一次应用层调用，三份共三次。

复用原文证据校验。B 的评语须指出无依据的婚恋断言，引用相关结尾段落作为审阅线索；单个局部引文不能证明全文都没有依据，仍需人工对照全文。

标注“Google 模板教学改编”，不称为 Google 官方服务，不暗示两种方法使用不同模型提供商。

### 并列展示

主输出为“摘要 ID / 覆盖率 / 综合质量 1–5 / 主要观察”矩阵；随后展开逐项命中、四项评语和原文引文。

两个分数不相加、不换算成共同百分制、不计算“综合方法比覆盖率提高多少分”。

## 6. 课堂流程（15–20 分钟）

1. 2–3 分钟：展示原文、摘要任务与五个要点，说明固定输出、切换评估方法。
2. 3 分钟：先看 B，学生指出正确内容和额外断言，预测两种结果。
3. 4–5 分钟：同稿双评，检查逐点结果与原文证据。
4. 3–4 分钟：加入 A/C，展示配对矩阵，区分覆盖且正确、覆盖但编造、正确但遗漏。
5. 3–5 分钟：回到事故摘要。写到了根因、影响和待办，是否保证没有编造数字？只优化覆盖率会漏掉什么？

与后续 Prompt A/B 的关系：本 Demo 固定输出、改变评估方法；后续实验固定评估标准、改变生成 Prompt。两类实验的变量不能混在一起。

## 7. 输入契约和实现方式

### 唯一共享 fixture

沿用综合评分器已有的 instruction/messages/summaries 命名，增加要点与来源：

```json
{
  "source": {
    "title": "木兰辞",
    "url": "<核验后填写>",
    "accessed_on": "<YYYY-MM-DD>",
    "edition_note": "<版本说明>"
  },
  "instruction": "<固定摘要任务>",
  "messages": [{"id": "p01", "text": "<原文诗段>"}],
  "must_include": [
    {"id": "k1", "text": "<要点>", "message_id": "p01", "quote": "<连续原文>"}
  ],
  "summaries": [{"id": "A", "text": "<固定摘要>"}]
}
```

这是结构示例，最终文件必须包含完整原文、五项要点和三份摘要。调用前校验类型、非空值、唯一 ID 及要点引文真实性。

两条 adapter 读取同一 input 和相同摘要 ID/text：覆盖率使用要点和摘要；综合评分使用任务、原文和摘要。报告保存共享输入及指纹，证明配对数据一致。

### 文件规划

```text
session-05-evaluation/
  compare_evaluators.py
  fixtures/mulan_eval.json
  fixtures/mulan_eval_mock.json
  MULAN_TEACHER_GUIDE.md
tests/
  test_session05_compare_evaluators.py
```

最小改造现有实现：

- `judge.py`：提取接受显式 points 的函数，返回逐点结果；新入口支持严格响应校验、原始输出与异常记录。旧 evaluate(summary, spec_name) 和默认事故 CLI 保持可用。
- `judge_google.py`：提取共享 `evaluate_summary()`，支持原始回放响应；两种入口各自先校验回放指纹。默认保持原有事故样例，复用真实调用和 parse_verdict。
- `compare_evaluators.py`：加载共享输入，编排两种方法，输出矩阵和报告；显式统一两条路径的模型配置与 temperature 等参数，允许响应长度上限因输出格式不同而不同并记录。
- 复用 `common.llm`，不复制成新的木兰专用评分器，不新增生成链路。
- 更新 Session 5 README 和 L4 教案的演示段，说明新例子的教学位置和事故场景迁移。

现有 Google 模板原则上不因更换语料而修改。共享客户端可能进行网络重试，与应用层评估次数区分。

### CLI

```bash
python course-demos/session-05-evaluation/compare_evaluators.py --mock
python course-demos/session-05-evaluation/compare_evaluators.py
python course-demos/session-05-evaluation/compare_evaluators.py --summary-id B
python course-demos/session-05-evaluation/compare_evaluators.py --input my_eval.json
```

默认使用木兰 fixture，执行全部三份摘要；--summary-id 只筛选执行对象。--input 可评其他原文，但必须提供对应原文、任务、要点和摘要，不能套用木兰清单。

### 报告及失败行为

保存至 `course-demos/outputs/evaluator-comparison/<run-id>/report.json`：

- 完整共享输入、SHA-256 指纹、实际执行摘要 ID。
- 两种方法的实际提示词、版本、provider/model、参数、模式、UTC 时间及应用层调用次数。
- 每份摘要的逐项 verdict、hits/total/coverage，以及 score/feedback/evidence。
- 原始响应、错误；两种方法分别标注 ok/error。执行错误的对应数值为 null。

一条方法失败仍运行另一条，但不能把缺失结果当成完整比较。任一 error 使 CLI 非零退出；低分不等于执行错误。不记录 API Key。

## 8. 离线模式及范围

旧 judge 的 token_overlap 只提取 `[a-z0-9]+`，不能合理评价纯中文。本 Demo 不使用这一 fallback，也不将它作为第三种有效评估方法。

无 Key 或 --mock 时，两条方法统一使用人工示例回放，标注 `mock_replay` / `human-authored-examples`。完整输入、两种方法的提示词和规则版本均绑定指纹；筛选 B 时仍验证完整 fixture。

输入或规则变化后拒绝使用旧回放。真实 API 失败不切换人工分数。回放也须通过相同结果校验，仅说明流程与指标含义，不证明模型能力。

本期不加入 ROUGE、中文词面相似度、审美评分、多模型对照或自动修复。

## 9. 验收标准

### 内容与教学

- 原文完整、来源可追溯；要点有依据且与任务一致。
- B 保留全部正确要点，仅额外新增无依据重要断言；C 仅保留前两项。
- 每份摘要两条路径的文字完全相同，教师标签和人工分数不进入请求。
- 同时展示两种尺度及其盲区，不换算统一准确率。
- 教案能回答：为什么同一份摘要覆盖率高，综合质量却可能低？

### 自动验证

- 输入、唯一 ID、要点引文与空要点列表校验。
- 两条路径收到正确的同一摘要及各自上下文，没有生成调用或教师答案泄漏。
- 覆盖率计算和 YES/NO 严格解析正确，异常不作为 MISS。
- 综合评分沿用既有字段、分数、引文校验。
- 人工回放两种结果可运行，输入/提示词篡改后拒绝回放；中文路径不调用旧 token_overlap。
- 单方法失败保留另一条结果与原始响应，状态及退出码正确。
- 原有 judge、judge_google 及相关测试继续通过。

### 真实模型验证

有模型配置时运行三稿双评，保存实际矩阵和报告。人工检查 B 的编造、C 的遗漏及与参考分的分歧；不将固定分数写成自动测试断言，不反复采样择优展示。没有模型时注明仅完成离线验证。

## 10. 完成标准

学生能说明：覆盖率测指定信息是否出现；综合评分还检查原文依据、任务完成情况和表达质量；单个指标高分不代表整体质量高。然后进入固定评价标准下的 Prompt A/B 实验。
