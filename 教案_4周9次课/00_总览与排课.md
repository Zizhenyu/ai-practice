# 企业级 AI 智能助手实战营 · 4 周 9 次课 · 教案总览

> **形式**：**全程远程在线**（平台无关：Zoom / 腾讯会议 / 钉钉 / Discord 均可，教案统一用「分组讨论室」「投票」「聊天区」「录制」这类通用说法）
> **班型**：小班 **5–10 人**（人人开麦、人人共享屏幕、人人答辩）
> **课时**：4 周 × 每周 2 次（周三 / 周日）+ **第 4 周加课 1 次** × 2 小时 = **9 次课 / 18 学时**
> **基准**：本仓库现有可运行代码（`course-demos/` 的 14 个 session + `slack-simulator/` + `demo-openclaw/`）
> **原则**：教案里写的每一条命令，讲师都能在无 API key 的机器上原样跑通
> **配套**：分课 runbook 见 `L1_*.md` ~ `L9_*.md`

## 一、两个设计决定（以及为什么）

### 1. 顺序重排为渐进式，不再按 One-Pager 的 W1–W4 标题走

招生文案的 W1 一上来就是 Multi-Agent / RAG / Tools，而 LLM 基础排在 W3——**学员还没见过 `call_llm()` 长什么样，就要理解 agent 编排**。（这个问题最早记在 `_backup/四周课程计划_技术栈对照版.md` 里。）

本教案改为：

```
地基（L1-L2） → 单点能力（L3-L4） → 结构化与检索（L5-L6） → 编排与集成（L7）
              → 评分与批判（L8） → 对外暴露与上线（L9）
```

每一课的产物都是下一课的输入，最后一课把全部产物送进评分器。**对外招生文案不用改**——W1–W4 的四个标题仍然成立，只是课内顺序不同。销售话术与教学顺序的对照见第六节。

### 2. 课时结构与代码目录不是一一对应

代码有 14 个 `session-*` 目录（历史上按 12 节课设计，2026-08 加了 13/14），课程排的是 **9 次课**。映射见第四节。砍的是"重复的工程细节"，不是"能写进简历的东西"：被压缩的主要是 session-02（Slack API 细节）和 session-07（任务系统的工程琐碎逻辑）；**评估闭环（session-05 / 12 + `score_openclaw.py`）一分钟没砍**，因为那是本课程唯一别人抄不走的部分。

## 二、🖥️ 线上授课的七条硬规矩

远程教编程课最大的风险不是讲不好，是**时间被环境问题和沉默吃掉**。以下七条是全部 9 节课共用的执行纪律，每节课的 runbook 里不再重复。

### 规矩 1 · 作业课前收，课上不现场找

线下可以喊"把你的电脑转过来"，线上不行——切换共享、找文件、等加载，一次要烧掉 3 分钟。

**流程**：作业截止在**上课前 12 小时**（交到共享仓库 / 作业频道）。讲师上课前挑好 1–2 份，**提前在自己屏幕上打开好**，点评时直接切窗口。

> 教案里所有写「投屏某某作业」的地方，都默认这份作业已经在讲师屏幕上打开了。

### 规矩 2 · 双屏是讲师的硬件底线

主屏共享（终端 / 编辑器 / 在线白板），副屏放：学员画面宫格、聊天区、教案本身、计时器。

**只有一块屏的后果**：看不到有人举手、看不到聊天区在刷"我这里报错"、切窗口时学员看到你的桌面。

### 规矩 3 · 白板 = 在线白板，不是实体白板

教案里所有「板书」「白板」指的是**在线白板 / 可标注的空白页 / 平板手写**。

- 复杂的图（如 L2 的时序图、L8 的混淆矩阵）**提前画好空框**，课上只填内容——远程手写比线下慢一倍。
- 画完**立刻导出 PNG 发进聊天区**。学员抄不下来，但截图能存一辈子。

### 规矩 4 · 每 7 分钟一个互动锚点

线上讲课超过 7 分钟没有互动，学员就开始刷手机。锚点不必复杂，四选一：

| 锚点 | 用法 | 成本 |
|---|---|---|
| **点名提问** | 小班可以直接叫名字。这是最有效的一种 | 0 |
| **聊天区打字** | 「跑通的打 1，报错的打 2」——3 秒拿到全班状态 | 0 |
| **投票** | 二选一的判断题（如 L7"这个场景需要多 Agent 吗"） | 30 秒 |
| **让学员共享屏幕** | 讲评环节的默认方式 | 1 分钟 |

**教案里标 🎤 的地方是必须做互动的位置**，不要跳过。

### 规矩 5 · 学员动手环节：静音自习 + 分组讨论室，不是讲师沉默

线下讲师巡场，线上必须显式设计。小班 5–10 人的标准做法：

```
0–2 min    讲师念一遍任务要求，确认无人有疑问        （主会议室）
2–20 min   静音自习。学员卡住 → 举手 / 聊天区打"卡住"
           讲师看到后把该学员拉进 1 号讨论室一对一     （不打断其他人）
20–25 min  全部回主会议室，抽 1–2 人共享屏幕讲自己的做法
```

**「举手 = 求助」这个约定必须在 L1 说清楚，并在每节课重复一次。** 线上学员卡住时倾向于沉默硬扛，这是远程教学最大的隐形损失。

**≥8 人时**改为：讲师留主会议室，助教开 2 号讨论室，学员自选进入。

### 规矩 6 · 每节课录制，并按段标注

教案里标 🎥 的段落是**明确建议回看**的（通常是概念密度最高、或代码跑得快的段落）。

**录制约定**（L1 第一次课就要说明，并取得同意）：

- 全程录制，课后 24 小时内发回放链接
- **学员共享屏幕的讲评段落**：开始前问一句「这段要不要跳过录制」，尊重不愿被录的人
- 回放只发给本班学员，**不做公开传播**
- 讲师课后在回放里标 3–5 个时间点（对应 🎥 段落），比给一整条 2 小时的链接有用十倍

### 规矩 7 · 网络与环境的应急预案

| 情况 | 预案 |
|---|---|
| **讲师掉线** | 助教接管，先播提前录好的演示片段；讲师 3 分钟内回不来则宣布休息 |
| **学员掉线** | 不等。回放能补。**在聊天区留一句"我们讲到 X"**，回来的人能自己接上 |
| **共享屏幕卡成幻灯片** | 停止共享 → 改发截图到聊天区 → 用嘴讲。**不要花 5 分钟修共享** |
| **现场跑的脚本报错** | 立刻切到提前跑好的截图，**课后再查**。远程 debug 会拖垮全班注意力 |
| **某学员环境彻底跑不起来** | 助教拉进讨论室处理；实在不行让他**先看着讲师跑**，课后补 |

> **提前跑好并留截图的清单**在每节课的「课前准备」里。这不是保险，这是必备品。

### 每课 120 分钟统一骨架（线上版）

| 时段 | 内容 | 线上执行动作 |
|---|---|---|
| **-10–00** | 讲师开播 | 提前 10 分钟进会议室，放着背景音/静默画面，让学员早到早调设备。**讲师此时完成"开播前 5 项检查"（见下）** |
| 00–08 | 上节作业点评 | 作业**课前已收好并打开**（规矩 1），直接切窗口 |
| 08–30 | 概念讲解 | 在线白板；**每 7 分钟一个 🎤 锚点**；画完的图导出发聊天区 |
| 30–58 | 现场演示（跑代码 → 读代码） | **先跑出结果，再回头读源码**，顺序不要反。学员在自己机器同步跑 |
| **50–60 之间** | 休息 **7 分钟** | 比线下长且更靠前。明确说「回来时在聊天区打个 1」，方便点人数。**休息时把下半场练习的要求贴进聊天区** |
| 至 95 | 学员动手 | 按规矩 5：静音自习 + 举手求助 + 一对一讨论室 |
| 95–110 | 讲评（**学员共享屏幕**）+ `pytest` 收尾 | 小班抽 1–2 人；每节课都以绿色测试结束 |
| 110–120 | 作业布置 + 下节预告 | 作业要求同时**打进聊天区**，不要只用嘴说 |

> ⚠️ **休息一律排在第 50–60 分钟之间**（线下版原本排在 70–75 分钟，线上不行——连讲 70 分钟必然掉线，注意力意义上的）。各课 runbook 的时间戳已按此调整：
>
> | L1 | L2 | L3 | L4 | L5 | L6 | L7 | L8 | L9 |
> |:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
> | 52′ | 50′ | 50′ | 55′ | 60′ | 60′ | 55′ | 55′ | 50′ |
>
> 连带效果：下半场的动手环节比线下版短 2–4 分钟。各课的练习时长已相应压缩，**runbook 里写的是压缩后的时长，照着执行即可**。

### 讲师「开播前 5 项检查」（每节课，2 分钟）

1. 终端**字号调到 18pt 以上**，配色高对比（远程看小字是灾难）
2. 关掉通知（系统 / 微信 / 邮件），关掉不相关的浏览器标签页
3. 本节课要跑的命令**全部预跑一遍**，确认能跑通（见各课「课前准备」）
4. 提前跑好的**截图放在一个文件夹里，按顺序命名**（应急用）
5. 开始录制，并在开头说一句「本节课录制中」

## 九、🖥️ L0 · 开课前环境验收（30 分钟，必做）

> **这是远程课最值钱的 30 分钟。** 线下学员环境挂了可以走过去看一眼；线上一个人的环境问题会吃掉全班 15 分钟。**把它全部挡在 L1 之前。**

### 形式

开课前 2–3 天，开一个 30 分钟的会议室。**不讲课**，只做三件事：设备调试、环境安装、跑通验收命令。小班可以一起做，卡住的单独拉讨论室。

### 学员侧验收清单（跑通并把输出截图发到作业频道）

```bash
git clone <课程仓库> && cd <仓库>

python --version                                    # 需 >= 3.9
python -m pip install -r course-demos/requirements-dev.txt  # 已包含 requirements.txt

pytest -v                                           # 应全绿
python course-demos/session-01-setup/check_env.py   # Summary 中 core deps 应为 ready
```

> `check_env.py` 中可选 LLM SDK 和尚未配置的 API key / Slack 凭据可以显示 `MISSING`，不影响 mock 模式验收；以 `Summary` 中的 `core deps: ready` 为准。只有要调用真实模型时才安装对应 SDK：OpenAI 或 DeepSeek 使用 `python -m pip install openai`，Anthropic 使用 `python -m pip install anthropic`。同时必须配置对应的 API key；否则使用 mock 模式。

### 设备侧验收清单

| 项 | 要求 | 为什么 |
|---|---|---|
| 麦克风 | 能出声，最好有耳机 | 外放会造成回声，一个人回声全班遭殃 |
| 共享屏幕权限 | **实测共享一次** | 很多人第一次共享时才发现系统没给权限（尤其 macOS） |
| 屏幕空间 | 能同时看会议 + 自己的编辑器 | 只有一块小屏的学员建议用手机看会议、电脑写代码 |
| 网络 | 能稳定跑视频 | 不行就关摄像头保带宽 |

### 讲师侧要在 L0 完成的事

- 建好**作业提交渠道**（仓库 / 频道），说明作业**上课前 12 小时**截止（规矩 1）
- 说明**举手 = 求助**的约定（规矩 5）
- 说明**录制政策**并取得同意（规矩 6）
- 记录每个人的环境状态，**把有问题的人标出来**，L1 前解决

### 验收标准

**`pytest -v` 全绿 + `check_env.py` 无 MISSING + 成功共享过一次屏幕**。三项齐了才算通过 L0。

## 十、验收与结营标准

| 项 | 及格线 | 优秀 |
|---|---|---|
| 代码 | 9 课练习全部提交，`pytest` 全绿 | 额外补了至少 1 个新功能（新中间件 / 新 agent / 新评分器 / 新护栏规则） |
| 评估报告 | 能跑出 P/R/F1 三个数 | 能解释**为什么规则版 0.90 高过 LLM 版 0.71**，并动手改了评分器 |
| **部署** | **README 里有一个能点开的 URL**，`/healthz` 有响应 | MCP server 接进过真实客户端，有"模型调用了你的工具"的截图 |
| **局限清单** | Known limitations 至少四条 | 每条都写清"什么时候会咬你"和"怎么修" |
| Demo | 5 分钟讲完流水线四段（**共享屏幕实操，不是念稿**） | 接受提问不卡壳 |
| 简历 | 写出一句带数字的项目描述 | 被追问"这数字怎么算的"能答出标注量、阈值、漏了什么 |
| 🖥️ 参与度 | 9 节课到 7 节以上，作业按时交 | 主动在讨论室帮别人排错——**这一条在推荐信里最值钱** |

> 及格线是"跑通"，优秀线是"能被追问"。课上反复强调这两句：
>
> **面试官不会验证你的数字，他会问你数字怎么来的。**
> **他也不会 clone 你的仓库，他会点那个链接。**
